# 为什么核心不开源 / Why the core is closed

## 一句话

**开了壳，等于把门口怎么查证件写给了对手；开了核，等于把测谎仪电路图交给了骗子。**

## 具体原因 / Reasons

### 1. 检测规则的寿命按小时计

异常检测靠的是"阈值 + 权重 + 信号组合"。一旦源码公开，攻击者可以：

- 精确定位每一个阈值（比如"每分钟 47 次才触发"），把请求卡在 46 次
- 逐条构造"合法"请求，绕过每一条规则
- 用自动化脚本穷举权重组合，找到得分最低的路径

闭源不是为了让规则更"神秘"，而是为了让绕过成本从**读一遍代码**变成**做一轮黑盒实验**——前者十分钟，后者可能要几周，而且我们的规则还在变。

### 2. 信号组合本身会暴露身份关联方式

PWA 的核心能力是把"换 IP 的人"和"换 Cookie 的人"认成同一个人。关联逻辑（哪些字段参与指纹、如何加权、窗口多长）一旦公开，等于告诉对手"只要把这三样都换掉就认不出我了"。

### 3. 误封的代价

严格的防护必然有边界情况。核心里有大量针对"正常用户奇怪行为"的豁免（公司 NAT、IPv6 临时地址、爬虫白名单、老旧浏览器）。把这些豁免清单公开，等于公开一份"伪装成正常用户的配方"。

### 4. 壳已经足够强

开源部分不是空壳，它本身承担了：

- 所有输入的长度与格式约束（防超大 header / 畸形 cookie）
- 白名单与回环豁免（正常用户/内部调用永不被误伤）
- 决策缓存与熔断（核心挂了站点也不会挂）
- 统一的、不泄露信息的拒绝响应
- 审计日志（可追溯每一次判定）

即使有人不用核心，只拿壳搭一个"白名单 + 缓存"的网关，也是一个可用的基础防护。

## 我们不做什么 / What we do not do

- 不把"检测规则"伪装成"随机数"放进开源代码里
- 不发布"阉割版核心"让人逆向出完整逻辑
- 不接受"为了透明必须开源核心"的要求——检测引擎和加密算法不同，它的安全性来自不可预测性，而不是公开验证

## 对研究者的承诺 / For researchers

- 可以提供**行为说明**（输入什么、输出什么、为什么拒绝），不含阈值
- 可以提供**独立测试接口**，用你构造的请求打我们的判定器
- 发现误封，我们优先修豁免；发现漏放，我们优先加权

---

**核心不可信，故不开源。** 这句话在安全工程里的意思是：任何依赖"攻击者看不到"的机制，都必须假设它终有一天会被看到——所以核心除了隐藏，还必须能在被看到之后仍然有效。PWA 的核心设计同时满足这两点：不可预测，且每次判定都独立可验证。
